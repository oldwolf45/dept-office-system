# T2 开发契约 —— 计划管理（材料模块开发计划 V1.2）

- 阶段：T2（依赖 T0/T1；与 T3 衔接；P0）
- 上位依据：修正版 PRD §6（需求计划）、§5.1（编号）；办公系统 PRD §14
- 验收：A5（需求计划填报与审核流程）

## 1. 接口清单（统一 {code:0,data,message}，均在 /api/materials 下，requireAuth + requireMaterialsAccess）

### 计划
| 方法 | 路径 | 说明 |
|---|---|---|
| GET | /plans | 列表（按 month/planType/status 过滤，camelCase） |
| POST | /plans | 新增草稿（工段长/科室经办填报；生成 JH 单据号） |
| GET | /plans/:id | 详情（含 items 明细） |
| POST | /plans/:id/submit | 提交 draft→submitted（仅草稿可提交） |
| POST | /plans/:id/approve | 审核通过 submitted→approved（主任/科长；角色门禁 T10） |
| POST | /plans/:id/reject | 驳回 submitted→rejected（必填 reason） |
| GET | /plans/summary?month= | 供应科全厂汇总（按 unitName 聚合 count/approved/rejected） |

> 路由注册顺序：/plans/summary 须在 /plans/:id 之前，否则被 :id 通配吞掉。

## 2. 数据模型
复用 T0 建的 `plans` / `plan_items`（软删除）：
- plans: plan_no(UNIQUE)、month(YYYY-MM)、plan_type(workshop/section)、unit_code、unit_name、status(draft/submitted/approved/rejected)、reject_reason、created_by
- plan_items: plan_id、category_id(可空)、material_name、planned_qty、reference_price、planned_amount(=qty×price，入库即算)
- 金额 `planned_amount` 在写 plan_items 时由后端计算，前端只读展示。

## 3. 编号规则
计划单据号：`JH + YYYYMMDD + 3 位当日流水`（`nextDocNo('plans','plan_no','JH')`，T0 服务已落地，本阶段调用）。

## 4. 状态机
`draft → submitted → approved | rejected`。submit 仅 draft 可触发；approve/reject 仅 submitted 可触发，否则返回 4000。驳回必须带 reason，否则 4000。

## 5. 权限矩阵（沿用 T0）
本阶段接口仅需材料模块访问权（requireMaterialsAccess）。"工段长/科室经办可填报、主任/科长可审核、供应科可汇总"的**角色级门禁**在 T10 接入（按钮级），T2 仅按状态开放对应按钮，便于流程跑通与联调。

## 6. 操作日志
create/submit/approve/reject_plan 写入 operation_logs（action_type 同前缀），格式同办公系统 §5.16。

## 7. 错误码
沿用平台：4000（月份格式/明细空/数量≤0/已非草稿/已非提交态/驳回缺意见）、4040 计划不存在、4010 未登录、4030 无权限、5000 服务器错误。
