## 1. 产品目标与使用场景

### 1.1 业务背景

工厂有多个车间，各车间下设若干工段。所有材料由工厂供应科统一采购、统一发放，每月按固定节奏循环（原 PRD 月度表保持）。

补充：事业部科室消耗的物料（签字笔等）是**材料体系的一个部分**，同样经供应科统一采购发放。科室的物料需求纳入材料模块的计划管理，领用与材料生命周期联动（依据《接入需求文件》V1.2）。

### 1.2 产品目标

1. 每件材料一个编号，记录从采购到货 → 领用 → 回收 → 处置的完整生命周期，可随时查询。
2. 记清两本账：采购花销、旧料处置收入；收支用固定分类，不够随时新增。
3. 自动形成图表：按月 / 车间 / 类别汇总收支与材料流转数量。
4. 数据不丢：集中存储 + 平台统一备份，可恢复。
5. **与办公系统「科室记账-物料账」在计划与领用两环节联动**：物料作为材料的一部分在材料模块留完整生命周期，金额口径一致。

### 1.3 角色与账号

- 角色（材料模块自定义，归模块管）：工段长、车间主任、供应科；**新增 科室经办**（科室侧填报物料计划、确认领用）。
- 账号：全平台统一（工号 + 密码），由平台创建维护；材料模块不再自建账号表，只读当前用户角色决定工作区。
- 跨模块：同一人可挂多模块角色（如科长既管科室，又可作为科室经办 / 审核）。
- 科室计划审核：拟由科长（办公系统角色）审核，具体衔接在《接入管理 PRD》定稿（接入需求 §11）。
- 组织：计划填报 / 领用单位 = 车间 / 工段 与 科室 两类。

### 1.4 运行方式

合并后作为办公系统的一个模块，部署在平台服务器（阿里云），数据集中存储，由平台统一备份。浏览器访问（电脑 / 手机能打开，手机不专门适配）。工厂侧网络可达性部署时实测（接入需求 §10）。

## 5. 各模块第一版必要的数据和操作

### 5.1 账号与登录
不再自建。账号 / 密码 / 角色由平台提供；材料模块读取当前用户角色决定工作区与可见功能。

### 5.2 材料类别管理
保持原 PRD：新增、修改、停用（已用不可删）。

### 5.3 计划管理（扩展科室）
- 数据：计划单（month、填报单位类型=车间/科室、单位、提交人）、计划明细（material_name、category_id、quantity、remark）、status（待审核 / 已通过 / 已驳回）、review_comment、reviewer_id。
- 操作：工段长填本工段计划；科室经办填本科室物料计划；审核前可改。主任审车间计划；科长审科室计划（拟，接入 PRD 定）。供应科看全厂已通过计划汇总（含两类单位）。
- 规则：同一单位同一月份一份生效计划（单位可为工段或科室）。

### 5.4 采购管理
保持原 PRD：按类别登记采购，记金额 + 花销分类，未到货前可改。

### 5.5 到货与编号
- 编号规则：`CL + 到货日期(YYYYMMDD) + 类别两位序号 + 当日四位流水`（例 `CL20261125-03-0007`），系统生成、查重、数据库唯一约束兜底。
- 到货登记生成编号，初始状态"在库"，写生命周期事件。
- 打印 / 抄录编号可选，不强制打印硬件。

### 5.6 领用管理（扩展科室）
- 领用单位：工段 或 科室。供应科发放时选单位登记，材料状态 → 已领用。
- **联动（对接核心）**：科室领用登记时，关联办公系统物料账中对应领用记录（按材料编号 / 批次），双方数量一致；物料账侧可见该批物料的采购花销（经 purchase_id 取数），金额口径一致。

### 5.7 旧料回收 / 5.8 处置管理
保持原 PRD：回收登记状态 → 已回收；处置登记状态 → 已处置并产生收入记录。

### 5.9 收支分类管理 / 5.10 生命周期查询 / 5.11 图表汇总
保持原 PRD。生命周期查询须覆盖发给科室的物料，链条不断。

## 6. 模块关系与联动

### 6.1 内部业务流
计划 → 采购 → 到货编号 → 领用 → 回收 → 处置。计划审核通过才能采购；到货编号后才能领用；有编号才能流转。生命周期查询 / 图表汇总只读。

### 6.2 与物料账的联动（对接核心）
```
科室物料计划 ──(报计划)──▶ 材料模块计划管理 ──▶ 供应科汇总采购
                                         │
材料模块领用(领用单位=科室) ◀──(领用登记)── 办公系统「物料账」
        │                                     │
        └── 关联编号/批次、状态→已领用 ────────┘
        └── 金额口径一致（物料账领用数量/采购花销 ↔ 材料模块记录）
```
- 计划联动：科室物料需求进材料模块计划管理，随车间计划一起汇总报供应科。
- 领用联动：科室领用 = 材料模块领用记录（领用单位 = 科室，状态 → 已领用），物料账登记领用时关联材料编号 / 批次。
- 金额分开：物料账的"计划内 / 计划外、销账"记账流程保留在物料账（管钱 / 预算口径），材料模块管料（需求与流转口径），两套"计划"各管各的。
- 生命周期查询覆盖发给科室的物料。

## 8. 第一版必须完成的功能

## 11. 重写开发纪律（对照复盘修正）

本版重写（在办公系统内实现材料模块）须执行以下纪律，作为硬性要求写入开发契约：

1. **任务级测试先行**：每个接口 / 规则动手前先写可运行用例，写完即跑；阶段末跑全量做验收。不全套 TDD，但拿测试先行好处。
2. **调试四步法**：缺陷强制走 复现 → 最小化 → 追根因 → 修复并防回归；报错位置 ≠ 问题位置。
3. **代码评审检查单**：10 条以内（命名、组件 / 函数超长、any 违规、软删除落实、接口走 api 层、权限服务端 + 前端双校验…），验收前过一遍。
4. **Git 分支规范**：并入办公系统仓库；分支命名、合并时机、禁止直改主干、收尾打标签。
5. **验收标准唯一源**：本文 §10；验收 agent 只执行核对，无权制定 / 修改标准，改标准走 PRD 升版。
6. **开发契约**：每阶段一份（接口 / 权限 / 数据模型 / 错误码），冲突先报主调度不改口径；契约 / 评审单 / 验收单模板化沉淀。
7. **禁止**：删测试、跳测、降标准过关；串联依赖按依赖排，无依赖同层内 P0 先于 P1。

## 12. 数据模型与关键规则要点（重写参考）

- **状态机**：在库 → 已领用 → 已回收 → 已处置，只允许正向流转，每次流转写生命周期事件（material_events），禁止绕行。
- **编号**：`CL + 到货日期 + 类别两位 + 当日四位流水`，系统生成 + 查重 + 唯一约束。
- **计划 / 领用单位扩展**：plans、issue_records 等单位字段支持 车间 / 工段 与 科室 两类；同工段 / 同科室同月一份生效计划。
- **账号 / 权限**：不建用户表；角色（工段长 / 车间主任 / 供应科 / 科室经办）与权限点归材料模块，服务端强制校验。
- **金额联动**：materials.purchase_id 关联采购花销；科室领用关联物料账记录，数量 / 采购金额一致。
- **组织数据**：开发前需准备车间 / 工段 / 供应科 + 科室（作为领用单位）的基础组织清单。
