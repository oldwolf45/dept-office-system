## 1. 接口清单（backend/src/routes/materials.js，统一 {code:0,data,message}）

| 方法 | 路径 | 鉴权 | 说明 |
|---|---|---|---|
| GET | /api/materials/me | 登录 + 模块访问权 | 返回当前用户 hasAccess 与模块内角色列表（工作区壳渲染依据） |

> 材料类别/收支分类/计划/采购等 CRUD 在后续任务（T1~T5）按功能补全，不在此阶段。

## 2. 权限矩阵（后端唯一权威；前端只按 /api/auth/me 渲染）

- 模块访问权（平台层，接入管理 PRD §3.2 / M1）：
  - `module_access` 表为空（尚未配置任何授权）时，**默认开放**——所有在职账号可见材料模块（T0/T10 过渡期，便于内部推广）；
  - 一旦配置了任意授权，仅白名单内用户可见；无权限访问 `/api/materials/*` 返回 **4030**。
- 模块内角色（`module_role_map`）：工段长 / 车间主任 / 供应科 / 科室经办，由账号维护配置（T10 接入 UI）。T0 仅建表与读取，未写入示例角色。
- 菜单可见：仅当 `/api/auth/me` 的 `permissions.menus` 含 `materials` 时，前端顶部「材料管理」才渲染；手输 `/materials` 无菜单码则路由守卫导向 `/403`（复用现有 checkMenu 机制）。

## 3. 数据模型（本阶段新增表，全部软删除 deleted_at，随平台统一备份）

新增表：material_categories、finance_categories、plans、plan_items、purchases、materials、material_events、issue_records、recycle_records、disposal_batches、disposal_items、module_role_map、module_access。

物料账联动（接入管理 PRD §4.2，T8 使用）：现有 `material_issues` 表幂等补列 `material_issue_id` / `material_codes` / `material_plan_id`，原数据不动。

种子：finance_categories 空库预置 3 条（采购支出/处置收入/回收残值），T1 起界面可维护。

## 4. 单据/材料编号规则（PRD §5.1 / §5.5）

- 单据编号（采购/领用/处置单）：`类型前缀 + 年月日(YYYYMMDD) + 3位流水`，如 `JH20261101001`，由 `materialsService.nextDocNo` 生成，当日唯一。
- 材料编号（每件材料生命周期码）：`CL + 到货日期(YYYYMMDD) + 类别两位 + 当日四位流水`，如 `CL20261101050001`，由 `materialsService.nextMaterialCode` 生成。

## 5. 操作日志（格式同办公系统 §5.16）

- T0 仅建表与访问中间件，尚未产生关键动作日志（计划审核/采购/到货/领用等日志在 T2~T5 按动作写入 operation_logs）。
- 访问拦截（无权限 4030）沿用统一响应，不单独写日志。

## 6. 错误码（沿用平台约定；材料模块段 6xxx 预留）

- 4010 未登录；4030 无权限（模块访问权/角色）；4000 参数错误；5000 服务器错误（与现有 response.js 一致）。
