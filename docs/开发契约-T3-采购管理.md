# T3 开发契约 —— 采购管理（材料模块开发计划 V1.2）

- 阶段：T3（依赖 T0~T2；与 T4 衔接；P0）
- 上位依据：修正版 PRD §7（采购管理）、§5.1（编号）；办公系统 PRD §14
- 验收：A6（按类登记采购与金额、可作废）

## 1. 接口清单（统一 {code:0,data,message}，均在 /api/materials 下，requireAuth + requireMaterialsAccess）

### 采购
| 方法 | 路径 | 说明 |
|---|---|---|
| GET | /purchases | 列表（month 按 purchase_date 前缀、categoryId、status 过滤，camelCase） |
| POST | /purchases | 登记采购（生成 CG 单据号；关联 plan_id/category_id/fund_category_id 均可空） |
| GET | /purchases/:id | 详情 |
| POST | /purchases/:id/void | 作废 normal→void（必填 reason，已作废不可再作废） |

## 2. 数据模型
复用 T0 建的 `purchases`（软删除）：purchase_no(UNIQUE)、plan_id、category_id、supplier、item_desc(非空)、amount(≥0)、fund_category_id(收支分类，采购支出类)、purchase_date(YYYY-MM-DD)、handler、status(normal/void)、void_reason。

## 3. 编号规则
采购单据号：`CG + YYYYMMDD + 3 位当日流水`（`nextDocNo('purchases','purchase_no','CG')`，T0 服务已落地，本阶段调用）。

## 4. 状态机
采购：`normal → void`（单向作废）。作废须带 reason，否则 4000；非 normal 状态作废返回 4000。作废仅标记状态与意见，不做物理删除（软删未启用，符合"作废留痕"语义）。

## 5. 权限矩阵（沿用 T0）
本阶段接口仅需材料模块访问权（requireMaterialsAccess）。"仅供应科可登记采购"的角色门禁在 T10 接入（按钮级），T3 暂不限制角色。

## 6. 操作日志
create/void_purchase 写入 operation_logs（action_type 同前缀），格式同办公系统 §5.16。

## 7. 错误码
沿用平台：4000（摘要空/金额负/日期格式/已非 normal/作废缺意见）、4040 不存在、4010 未登录、4030 无权限、5000 服务器错误。
