# T10 开发契约 —— 平台接入收尾

- 阶段：T10（依赖 T0~T9 + 接入管理 PRD）
- 依据：《接入管理 PRD》V1.0 §3/§7（M1~M6）
- 验收：A1、A10、A11、M1~M6

## 1. 账号与访问权（M1/M2）
- 无独立账号表：材料模块复用平台 `users` + JWT，无独立登录页（M2）。
- 模块访问权：`module_access`（用户-模块关系）。`module_access` 空 = 默认开放（过渡期）；一旦配置，仅白名单可见；无权访问 `/api/materials/*` → 4030（M1，已测）。
- 菜单码 `materials` 由 `/api/auth/me` 的 computePermissions 按 hasModuleAccess 下发，前端按菜单渲染入口。

## 2. 按钮级权限（前端不渲染 + 后端拒绝）
- 后端权威：`requireMaterialsRole(...roles)` 中间件，按 `module_role_map` 角色拒绝 → 4031。
  角色矩阵：计划填报 `workshop_director|section_agent`；计划审核 `workshop_manager|supply`；采购/到货/领用/回收/处置 `supply`。
- 前端：`composables/useMaterialsAccess.ts` 取 `/me` 角色，按角色不渲染对应按钮（PlanView/PurchaseView/ArrivalView/FlowView）。

## 3. 集成项映射（M1~M6）
| 项 | 实现 |
|---|---|
| M1 模块访问权 | module_access + requireMaterialsAccess → 4030 |
| M2 账号统一 | 复用平台 users/JWT，无独立登录 |
| M3 升级无损 | 仅新增表/列（幂等 ALTER），不动原表数据 |
| M4 领用联动 | 科室领用写 material_issues（material_issue_id/material_codes/qty 一致） |
| M5 计划联动 | 科室计划随供应科全厂汇总（summaryPlans） |
| M6 操作日志 | 各关键动作写 operation_logs（同 §5.16 格式） |

## 4. 部署与备份（A10/A11，需服务器执行）
代码层已满足：数据随平台统一 SQLite（`./data`）与平台备份脚本；材料模块代码并入现有前后端容器，不新增容器。**线上部署（阿里云）与备份恢复实测需在有服务器权限的环境执行**，见 T11 交付说明。
