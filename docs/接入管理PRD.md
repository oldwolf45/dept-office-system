## 1. 接入总览

```
遗留事业部办公系统（平台）
├── 现有模块：工作管理 / 科室记账（含物料账）/ 汇总统计 / 工作总结 / 系统设置
└── 新增模块：材料管理（materials）
      ├─ 角色：工段长 / 车间主任 / 供应科 / 科室经办
      ├─ 功能：计划 / 采购 / 到货编号 / 领用 / 回收 / 处置 / 收支分类 / 生命周期 / 图表 / 首页
      └─ 与「物料账」联动：计划（科室需求并入） + 领用（双向关联，金额一致）

技术事实：合并为一个系统 = 一个前端工程 + 一个后端工程 + 一个 SQLite 库。
材料模块与物料账是同一库内的表关联，不是跨服务接口调用。
```

## 2. 页面与导航落点

- 平台顶部导航新增「材料管理」入口，仅对拥有模块访问权的用户显示。
- 材料模块内部按角色分工作区（修正版 PRD §2）：工段长 / 车间主任 / 供应科 / 科室经办 各自的菜单与首页。
- 材料模块角色登录后进入**材料工作台**（进度条 / 收支概览 / 待办 / 快捷入口，修正版 PRD §3），不进办公系统工作台。
- 一人兼多角色（如科长既是办公科长也是材料模块科室审核人）：顶部同时出现「办公系统」与「材料管理」模块入口，各自进各自工作台。
- 导航结构遵循办公系统现有范式（一级菜单 + 左侧分组菜单 + 内容区），样式用 Element Plus + Tailwind（同 §2.3 约定）。

## 3. 权限与账号

### 3.1 平台账号统一
- 材料模块**不建独立账号表**，复用平台账号（工号 + 密码 + JWT）。登录后平台在 `/api/auth/me` 返回：用户基本信息、办公角色与层级、所属科室、已授予的模块访问权。
- 材料模块读取当前用户判定模块内角色与可见功能。

### 3.2 模块访问权（平台层）
- 新增「模块访问权」配置：在平台账号管理页，给指定用户勾选「材料管理」模块访问权。无此权者：看不到「材料管理」菜单，直接访问 `/api/materials/*` 返回 403。
- 授权人：沿用办公系统账号维护权限（科长及以上可对下级授权）。
- 配置数据落平台「用户-模块」关系表，随平台统一备份。

### 3.3 模块内角色（归模块管）
| 材料模块角色 | 由谁担任 | 主要操作 |
|---|---|---|
| 工段长 | 平台用户被指派为某工段工段长 | 填报本工段计划、领用/回收登记 |
| 车间主任 | 平台用户被指派为某车间主任 | 审车间计划 |
| 供应科 | 平台用户被指派为供应科 | 计划汇总、采购、到货、发放、回收、处置、分类、图表 |
| 科室经办 | 平台用户被指派为某科室经办 | 填报本科室物料计划、确认领用 |

- 角色通过「用户 ↔ 模块角色 ↔ 单位（车间/工段/科室）」映射确定，初始在账号维护时配置。
- 一人可挂多模块角色（如某人既是工段长又兼科室经办）。

### 3.4 科室计划审核衔接（锁定接入需求 §11 待定项）
- **规则：科室物料计划由该科室科长审核。**
- 技术实现：平台在每个请求返回用户办公角色层级（level）与所属科室；材料模块判定「科室计划审核权」= 平台用户 level ≥ 3 且 所属科室 = 该计划填报科室。不另立材料模块审核角色，复用平台既有的科长身份与科室归属。
- 流程：科室经办填报 → 科长审核（通过 / 驳回，驳回必填意见）→ 供应科在计划汇总中可见（随车间计划一起）。

### 3.5 按钮级权限
- 沿用办公系统按钮权限模式（前端不渲染 + 后端接口拒绝）。
- 材料模块按钮权限码（建议）：`material-issue`（发放）、`material-dispose`（处置）、`material-backup`（备份，若模块内保留）、`material-category`（分类管理）。具体在阶段契约定。

## 4. 数据模型与联动

### 4.1 表归属
- 材料模块表（修正版 PRD §12）：material_categories / finance_categories / plans / plan_items / purchases / materials / material_events / issue_records / recycle_records / disposal_batches / disposal_items / module_role_map。
- 全部带 `deleted_at` 软删除，与办公系统一致。
- 这些表与办公系统现有表在**同一 SQLite 库**，随平台统一备份。

### 4.2 与物料账的关联字段（同库表关联）
物料账领用表新增关联字段（升级时加列，不动原数据）：

| 物料账侧字段 | 关联对象 | 说明 |
|---|---|---|
| `material_issue_id` | 材料模块 `issue_records.id` | 科室领用记录 ↔ 材料模块发放给科室的领用记录 |
| `material_codes` | 材料模块 `materials.code` 列表（JSON） | 该笔领用对应的材料编号集合，便于生命周期查询回溯 |
| `material_plan_id` | 材料模块 `plans.id`（可选） | 若物料账领用引用某材料计划，关联之 |

- 关联在同库内通过外键 / 查询实现，无需跨服务 HTTP 调用。
- 材料模块发放给科室（领用单位 = 科室）时，写 `issue_records`，并由服务层在物料账写入对应领用登记（数量、采购金额、关联 `material_issue_id`）；物料账侧继续做发放给个人、结存等内部操作。

### 4.3 组织数据
- 升级前准备基础组织清单：车间 / 工段 / 供应科（来自材料业务）+ 科室（作为领用 / 计划单位，复用办公系统科室编码）。
- 人员 ↔ 模块角色 ↔ 单位 映射初值，在账号维护时配置。

### 4.4 数据迁移
- 办公系统原有全部数据**无损保留**，升级仅新增材料模块表与物料账关联字段，不改现有表结构、不迁现有数据。
- 材料系统原 Python 库仅测试数据，**不迁移**，模块从空账开始。

## 5. 物料账联动详细流程

### 5.1 计划联动
- 科室物料需求在材料模块计划管理填报（科室经办）→ 科长审核 → 供应科汇总（与车间计划同视图）。
- 物料账的「计划内 / 计划外、销账」记账流程保留不动（管钱 / 预算口径），与材料模块计划（管料 / 需求口径）各管各的；二者不自动同步内容，仅业务上科室需求经材料模块走供应科采购。

### 5.2 领用联动（核心）
```
供应科在材料模块「发放登记」：领用单位=科室 → 生成 issue_records（状态→已领用）
        │
        └─ 服务层同步在物料账写领用登记：数量、采购金额（经 purchase_id 取）、material_issue_id 关联
        │
物料账侧：用户可见该笔领用，可继续做「发放给个人 / 结存 / 销账」内部操作
        │
生命周期查询（材料模块）：按 material_code 可见该批物料已发给科室，链条不断
```
- **金额一致**：物料账领用的采购金额由材料模块 `purchase_id` 自动带出，不重复录入，杜绝两边对不上。
- **数量一致**：物料账领用数量 = `issue_records` 中该笔数量，关联字段校验。

### 5.3 其他联动
- 生命周期查询、图表汇总覆盖发给科室的物料（修正版 PRD §5.10 / §5.11）。

## 6. 系统升级方式

### 6.1 版本
- 办公系统当前 发行版 v1.0（GitHub 至 1.0.2）；并入材料模块后发 **v1.1**。
- 版本号、升级说明随发版更新（README / 发行版说明）。

### 6.2 升级与数据无损
- 升级 = 部署新代码 + 执行建表 / 加列迁移（材料模块新表、`material_issue_id` 等关联字段）。
- 现有表不动、现有数据不迁；迁移脚本幂等（已存在则跳过），保证可重复执行、可回滚比对。
- 数据随平台统一备份（SQLite 文件 + `./data` 卷），升级前自动备份一次。

### 6.3 部署
- 材料模块代码并入现有 frontend / backend 工程，随现有 `docker-compose.yml` 部署，**不新增容器**（只有 `api` + `web` 两个服务，数据卷 `./data:/app/data`）。
- **生产部署须在 `.env` 配置 `JWT_SECRET` 与 `MINIMAX_API_KEY`**：`docker-compose.yml` 默认 `JWT_SECRET=dev-secret-change-me` 仅用于本地，上线前必须改。数据持久化依赖 `./data` 卷挂载，升级不删该卷即可保数据不丢。
- 阿里云更新：重新构建 / 拉取镜像部署，验证可达性与功能；工厂侧网络可达性实测（接入需求 §10）。

### 6.4 发版
- 测试全通过后，推送办公系统仓库（GitHub `oldwolf45/dept-office-system`），合并 `feature/material-module` 到主分支，打标签 **v1.1.0** 并发版。
- 发布前不在外部渠道公开半成品。

## 7. 验收标准

功能验收见《材料系统修正版 PRD》§10（A1~A13）。本文件补充接入专项验收：

| 编号 | 验收项 | 检查方法 |
|---|---|---|
| M1 | 模块访问权：无「材料管理」访问权的用户看不到菜单，直接访问 `/api/materials/*` 返回 403 | 用无权和有权账号各试 |
| M2 | 账号统一：材料模块无独立登录页，用平台账号进入，角色工作区正确 | 平台账号登录后进材料模块 |
| M3 | 升级无损：升级后办公系统原工作 / 记账 / 统计 / 总结数据全部可查可操作，历史不丢 | 升级前后核对原数据 |
| M4 | 领用联动数据一致：物料账领用记录与材料模块 `issue_records` 关联，数量 / 采购金额一致；生命周期可见发给科室的物料 | 造一笔科室领用，两边核对 |
| M5 | 计划联动：科室经办报计划 → 科长审核 → 供应科汇总含该计划 | 走完整科室计划流程 |
| M6 | 操作日志：材料模块关键动作（审核 / 采购 / 到货 / 领用 / 回收 / 处置 / 作废）写入操作日志，格式同办公系统 §5.16 | 查日志 |
| M7 | 发版：阿里云更新完成 + GitHub 标签 v1.1 存在 | 验证线上与仓库 |

## 8. 风险与待定

1. **同库关联**：本文件按"合并为一个系统 = 一个库"设计联动为表关联。若平台实际为分库 / 多服务，T8 改为服务间接口联动，需回到开发计划调整（当前按计划 V1.1 假设同库）。
2. **组织数据准备**：车间 / 工段 / 供应科 / 科室清单与人员-角色映射须在 T10 前就绪，否则发放 / 审核无法跑通。
3. **工厂侧网络**：T10 部署实测阿里云对工厂侧可达性。
4. **按钮权限码**：具体码值在阶段契约（第 6 部分模板）定稿，本文件给建议值。
